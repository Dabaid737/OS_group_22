## 三、实验整体逻辑分析

### 2.1 本章节的逻辑主线
1. **关键词：** 内核的内存设置、入口点设置、OpenSBI封装输出函数
2. **现实中的操作系统（下面所说的是部分操作系统选取的运行方式）：**
外部的编译工具链生成操作系统内核镜像 → 通过bootloader程序从硬盘中加载到内存中并启动内核 → 由bootloader、操作系统内核确保当前满足sp栈指针合法、CPU状态正确等条件 → 构建C语言函数可运行的环境（没有标准库无法使用printf） → 内核调用自行实现的输出函数输出启动日志 → 后续其他操作
3. **本章实验中最简单内核：**
下载的工具链编译生成操作系统内核镜像 → QEMU将作为bootloader的OpenSBI加载到0x80000000上，将内核镜像加载至模拟物理内存的0x80200000位置 → OpenSBI完成初始化并启动内核使内核获得执行权 → 通过entry.S设置初始栈 → 构建C函数运行所需环境 → 内核调用cprintf函数输出交互。

说明：C函数环境的构建，即满足sp栈指针合法，CPU状态正确等条件，条件全部满足，环境构建完毕。本实验中，CPU状态等其他条件由OpenSBI完成，entry.S负责设置初始栈并确定栈顶指针sp位置正确。

### 2.2 功能的逐步实现


1. **首先生成内核镜像，并为镜像规定入口以及内存布局。** `Makefile` 使用预先下载的 `riscv64-unknown-elf-` 工具链编译汇编文件和 C 文件，再由工具中的链接器`kernel.ld` 链接生成一个ELF文件 `bin/kernel`。在这里，链接器将内核的起始地址设为 `0x80200000`，以 `kern_entry` 为入口，并将各个汇编语言、C语言的代码段、只读数据段、数据段和 BSS 段统一起来，定义初始化时需要的 `edata`、`end` 等符号。随后通过 `objcopy` 生成二进制镜像（bin文件） `bin/ucore.img`。这主要是因为OpenSBI来说，ELF过于复杂。

2. **接着加载镜像，由固件将执行权交给内核。** `make qemu` 启动 QEMU 的 `virt` 机器，使用 OpenSBI 固件，同时QEMU将 `bin/ucore.img` 加载到地址0x80200000。OpenSBI 完成早期启动后，将执行权交给该地址处的内核入口。

3. **进入汇编入口后，先建立内核栈，再跳转到C函数。** `entry.S` 在 `.data` 段中预留 `KSTACKSIZE` 字节作为启动栈；由 `KSTACKPAGE = 2` 和 `PGSIZE = 4096` 可知，栈大小为 8192 字节。`bootstack` 和 `bootstacktop` 分别标记这片空间的低地址边界和高地址边界。入口执行 `la sp, bootstacktop`，将栈顶地址写入栈指针寄存器，然后执行 `tail kern_init`，跳转到 `init.c` 中的 C 入口而不为这次跳转设置返回地址。（这里可直接联通后续练习一）

4. **进入 `kern_init` 后，先让BSS段内数据均为0，为后续C代码准备初始数据状态。** `kern_init` 通过 `extern char edata[], end[]` 引用链接脚本提供的边界符号，并调用 `libs/string.c` 中的 `memset(edata, 0, end - edata)`，将该范围内的内存清零。这一步用于保证未显式初始化的全局变量和静态变量（BSS段）具有预期的零初值，是搭建C函数可正常工作环境的一步。至此，C函数可工作的环境已经搭建完毕。

5. **调用已封装跨越特权级别调用OpenSBI的函数cprintf输出启动信息。** 
补充说明信息：
①为何使用SBI？缺乏标准库，自行实现输出需要借助固件OpenSBI提供的控制台输入输出服务
②为何使用内联汇编？ecall是汇编指令，但此时已经进入了kern_init.c这个C函数中，此时必须使用内联汇编。
③如何调用SBI？OpenSBI作为固件其特权级为M级机器级，而内核为S级操作系统内核级，无法通过call调用，因而必须使用**ecall**，并遵守一个调用约定，包含指定服务编号，按约定传递参数，调用和返回返回值几个步骤。做这件事时，CPU就类似在进程丢失运行权时做的那样，trap到M级，为内核调用OpenSBI，并由它处理请求。
多次封装与多次调用过程：
kern_init
  → cprintf
    → vcprintf
      → vprintfmt
        → cputch（每个字符调用一次）
          → cons_putc
            → sbi_console_putchar
              → sbi_call
                → ecall：从 S 模式trap到 M 模式
                  → OpenSBI 处理字符输出
                  → 返回 S 模式，继续输出下一个字符

6. **输出完成后，进入无限循环，保持内核执行状态。** `kern_init` 最后执行 `while (1)`，进入一个死循环。

#### 问题一：指令 la sp, bootstacktop 完成了什么操作，目的是什么？

**前置代码和汇编指令解析：**

在entry.S这个汇编文件中，有

bootstack:

  .space KSTACKSIZE

  .global bootstacktop

bootstacktop:

其中，bootstack、bootstacktop均为标号，代表了两个地址，.space是汇编器指令，用于在汇编后链接前预留出一片KSTACKSIZE字节长的区域，KSTACKSIZE在memlayout.h和mmu.h两个头文件中宏定义，具体计算为内存栈的页数*页大小(2*4096=8192)。.global也是汇编器指令，它把符号 bootstacktop 声明成一个全局符号，让链接器和其他目标文件能够看到这个标号。这一段代码在内存上划分了一片大小8192字节的栈区域供内核使用，并把栈顶地址存在bootstacktop这一全局标号中。

指令la是一个伪指令，即"load address"的缩写，具体操作是读取右操作数的地址，并把读取到的地址存在左操作数里。 la sp, bootstacktop就是将刚刚划分的栈的栈顶地址加载给sp栈指针寄存器。

**该操作的目的是：**

未执行这一指令前，栈指针寄存器中保存的仍是上一启动阶段留下来的值（固件OpenSBI使用的栈区域），而未来进入操作系统内核，不再使用汇编语言后，C语言编写的函数工作通常就都需要栈了，例如函数可能要保存返回地址等等。这时就需要提供一片内核能够直接控制的栈区域。由于栈是由高地址到低地址的，这时我们让sp栈指针指向bootstacktop所存的地址，那么从bootstack标号对应的地址到bootstacktop标号对应地址之间提前预留好的区域，便可作为内核可操控的栈区域使用了。

#### 问题二：指令 tail kern_init 完成了什么操作，目的是什么？

**指令及调用的对应函数解析：**

指令tail是一个伪指令，即尾调用（AI给出的名词），通常意义上的call需要在寄存器ra中保留一个返回的地址，而尾调用不保留返回地址，PC只jump过去，不再回到entry.S；kern_init 是定义在init.c中的函数，在本次实验中kern_init中调用了用户自己编写的"memset"，用于清除bss数据段，还调用了我们通过SBI调用编写的cprintf函数，输出(THU.CST) os is loading ...字样，最终进入死循环

**该操作的目的是：**

在la sp，bootstacktop指令后，计算机完成了对操作系统内核栈的初始化，准备将操作权转让给操作系统内核；kern_init正是操作系统内核的入口点，这里操作系统与用户第一次进行交互，输出了os is loading的字样，未来的功能都由这里开始继续实现。
